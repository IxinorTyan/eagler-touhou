# 东方灵异传 · 多玉与合作联机

基于 ReC98 `debloated` 分支魔改《东方灵异传》，现已参照 TH03／TH04 更换为 **DOSBox-X / PC-98** 内核。支持单人多玉、本地双人／三人合作、局域网和公网联机，提供触屏操作、独立残机与 Bomb、幽灵救援和不限次数续关。

单人和本地合作使用 JSPI；联机使用完整 Asyncify、确定性虚拟时间和固定 30000 cycles，沿用确认锁步。游戏文件从原有 HDI 提取到内置 DOS 执行，磁盘中的系统 DOS、VEM486 和 NP21 不参与运行。普通启动器直接使用随附内核，不需要本机安装 DOSBox。

仓库只发布可直接运行的分发文件：网页、已生成的游戏镜像、音乐、模拟器、服务端和启动器。无需编译游戏，也不依赖本机 TH03／TH04 目录、Borland、DOSBox 或音乐转换工具。开发源码、构建工具、测试和报告保留在维护者本地。

## 启动

需要 Python 3.10+，以及支持 WebAssembly、gzip 流解压和 Opus 音频的新版 Edge／Chrome。**单人和本地合作还需要 WebAssembly JSPI**；不支持时页面会明确提示。请通过服务访问网页，不要直接双击 HTML。

| 模式 | Windows 启动方式 | 入口与行为 |
| --- | --- | --- |
| 单人游戏 | `start.bat`，首页选择“单人游戏” | `solo.html`，进入原作主菜单 |
| 本地合作 | `start.bat`，首页选择“本地合作” | `local.html`，双人／三人直接进入第一关 |
| 局域网联机 | `start-lan.bat` | `lan.html?network=lan`，默认端口 9874 |
| 公网联机 | 房间服务配合 HTTPS 部署或临时公网隧道 | `lan.html?network=public`，全员访问同一个公网地址 |

单人和本地合作只需 Python 标准库，也可在项目目录手动执行：

```bash
python server.py
```

默认地址为 http://127.0.0.1:9871/ ，端口占用时向后寻找可用端口，以窗口输出为准。保持窗口打开，Ctrl+C 停止服务。

联机启动器会检查 `websockets` 16；首次使用先安装依赖：

```bash
python -m pip install -r requirements-relay.txt
python lan_server.py --no-browser
```

手机访问也使用 `start-lan.bat`，打开服务窗口给出的局域网地址，再选择单人、本地合作或联机。Windows 防火墙需要允许 Python 接收入站连接。首页入口不会自动启动房间服务。

公网临时测试需要已经安装且能从 PATH 调用的 cloudflared：保持房间服务运行，再执行 `start-public-tunnel.bat`，所有玩家打开它给出的同一个 HTTPS 地址。TURN 可通过 `configure-turn.bat` 配置。固定部署、打洞与转发说明见 [公网联机说明](README-PUBLIC.md)。

## 单人、多玉与续关

单人使用当前魔改游戏，保留原作主菜单、路线选择、关卡、结算和成绩登记；可选 1／2／3／4／6／8 玉。默认一玉，正常受伤，不启用合作幽灵与救援。本地合作和联机直接进入第一关，按射击键开球。

玉数是全场总数。一玉沿用原作运动；多玉从原作位置向不同方向发射，分开后启用玉之间的碰撞。阴阳玉会伤害存活玩家，御币和特殊动作沿用游戏判定。调试无敌默认关闭。

“多玉生命补偿”默认开启，也可关闭。每位玩家初始残机增加 `floor(玉数 / 2)`：

| 玉数 | 1 | 2 | 3 | 4 | 6 | 8 |
| --- | --- | --- | --- | --- | --- | --- |
| 额外残机 | 0 | 1 | 1 | 2 | 3 | 4 |

单人和本地合作分别保存设置；联机由房主统一设置。原作基础残机配置不被改写，续关恢复基础残机加本次补偿，以及每人 1 个 Bomb。

允许不限次数续关，Continue 菜单没有等待超时退出。单人／本地合作使用网页“续关”按钮或原作菜单确认，联机由房主选择“全员续关”，从当前关重开；选择不继续或主动退出仍返回主菜单。

## 操作与触屏

| 操作 | P1／单人 | 本地 P2 | 本地 P3 |
| --- | --- | --- | --- |
| 左右移动 | ← / → | A / D | F / H |
| 发射／射击 | Z | J | T |
| 御币／滑铲／特殊动作 | X | K | Y |
| Bomb | 原作 Z / X 双击组合，或左右同时按住加 Z | 对应 J / K 组合，或 A + D + J | 对应 T / Y 组合，或 F + H + T |

Esc 使用原作暂停；网页暂停按钮暂停模拟器。菜单可用方向键和 Enter 确认。联机每台设备都用 P1 键位操作自己的座位，房主操作路线、成绩登记和续关菜单；任意玩家可开球、请求暂停。

手机默认开启触屏，也可手动点击“触屏操作”。按住左／右按钮移动，松手停止；另一个手指可同时按射击、御币或独立 **Bomb** 按钮。Bomb 只消耗当前玩家的库存。菜单提供上下方向和确认按钮。

“按键与触控”支持调整按键位置、大小、层级、画面水平位置，横竖屏布局分别保存在当前浏览器。设置面板可拖动、收起。本地合作可选择触控 P1／P2／P3，联机自动控制自己的座位；请先暂停再编辑布局。

全屏仅显示游戏画面与浮动操作入口，不保留顶部工具栏、网页库存或音乐栏。右上角可打开设置或退出全屏，声音、画面档位和联机音乐音量收进设置面板。触控使用半透明按钮，菜单阶段显示方向键与确认，游戏中按住左／右按钮移动。浏览器无法进入原生全屏时使用铺满页面的布局。

受击复位期间保留游戏触控布局并暂时停用输入，不切换为菜单方向键；主菜单、暂停、成绩登记和续关仍提供菜单操作。

## 合作与救援

双人／三人共享场地、阴阳玉、关卡与团队分数，各自保存动作、射击、残机和 Bomb。游戏内与网页 HUD 显示各自库存，原生残机数字支持两位数。

有残机时中弹只扣自己的残机，在当前位置恢复并获得短暂保护；耗尽后再次中弹变成幽灵。网页状态栏显示中弹、保护倒计时和获救信息。开局及普通换关不会额外给予存活玩家保护。

幽灵可左右移动，不能击玉、射击或拾取道具。接触活着的队友立即免费复活，救援次数不限；阴阳玉穿过幽灵，不触发救援。获救后获得 169 个游戏帧的保护，正常速度约 3 秒，不补额外残机。进入下一关自动救起幽灵；全员成为幽灵才 Game Over。

幽灵复用 TH04 的灵梦美术，颜色适配当前 PC-98 调色板。死亡／救援使用原生 16／12 游戏帧的受击姿势、点阵和短促白色像素过渡。角色及 Boss 的局部补画处理弹幕擦除造成的图像缺口。

同一时间只运行一个全屏 Bomb，队友仍可移动和攻击，未成功发动不扣库存。

## Boss 减伤

人数和玉数选择处会标明 Boss 耐久倍率、减伤比例和每次有效命中的累计伤害：

```text
M = (1 + 0.5 × (人数 − 1)) × (1 + 0.15 × (玉数 − 1))
```

1 人 1 玉维持原作伤害；2 人 2 玉约 ×1.725，3 人 4 玉约 ×2.9，3 人 8 玉约 ×4.1。

Boss 血量格数、阶段阈值和受击保护保持原样。玉与 Bomb 的每次有效伤害累计 `1/M` 格，满一格才扣血，余量保留；未扣整格也有受击反馈。完整血池耗尽所需有效命中次数为 `ceil(原血量 × M)`，使用整数累计保证联机一致。

倍率按入场设置固定，幽灵与救援不改变它。独立补血阶段、重开和续关清空余量；原作计时与攻击次数触发的阶段切换仍生效，战斗时长不一定按倍率增长。

## 房间与联机

1. 全员打开同一个局域网或公网游戏网址。
2. 房主创建双人／三人房间，选择难度、玉数、生命补偿、座位、连接方式和输入缓冲。
3. 队友输入四位房间号加入，自动跟随房主设置，无需邀请链接。
4. 全员准备后房主开始；资源加载与版本校验一致后，直接进入第一关。

优先使用 **UDP 直连／打洞**，由 WebRTC DataChannel、ICE 和 STUN 建立连接；局域网默认无需 STUN，公网自动使用默认 STUN。配置 TURN 后可兜底，也可选择强制 TURN。另一种方案为同源 **WebSocket／WSS 服务器转发**。连接详情按实际选中的候选对显示路径与协议。三人采用房主分别连接两位队友的星形结构。

联机使用确认锁步，各端运行自己的模拟器，只交换输入与同步消息。输入缓冲默认**自动**：加载完成后由房主进行至少 5 次延迟探测，结合抖动选择 2～12 步缓冲，三人时计入队友经房主转发的两段路径；开局消息统一全员缓冲，本局固定。探测超过 2.5 秒未完成时采用保守缓冲（LAN 至少 3 步、公网至少 6 步）。也可手动选择 2／3／4／5／6／9／12 步。每步约 16.7 毫秒，例如 2 步约 33 毫秒、6 步约 100 毫秒；这些仅为输入缓冲时间，另有采样、网络等待和游戏处理时间。降低缓冲可改善响应，但网络波动时可能增加停顿。

自动模式也按测得的传输时间对齐开局节拍，避免房主提前起步消耗缓冲。键盘、触控按下／松开和缺失输入到达会立即检查推进条件，减少等待轮询的时间；已采样输入不会被改写，短按射击、御币和 Bomb 保留到正常采样。详情显示实际缓冲、往返延迟、抖动、网络等待比例和下次开房的缓冲建议（三人建议由房主查看）；建议不会自动改变当前设置。更新后请全员刷新页面并重新建房，服务器也需使用本版本，以支持自动缓冲设置。

全员输入到齐才推进。每 120 步在后台核对状态，未核对步数达到 240 才等待；版本或状态不一致会停止整局。UDP 短暂中断最多等待 10 秒恢复原连接，明确失败、通道关闭或超时则停止。隐藏页面会拖慢全员，长时间隐藏会终止本局。

当前不支持回滚、主机迁移、断线重新加入或局中切换传输。直连失败时重新建房，选择已配置的 TURN 或服务器转发。网络断线不会转成游戏内幽灵。跨 NAT 打洞、真实手机和公网性能仍需实际环境测试。

## 音乐与性能

仅联机模式将 BGM 与游戏锁步分开：浏览器按游戏选曲播放本地 Opus 音乐，网络等待不暂停音乐、不改变音高；音效仍由原生游戏输出。音乐音量只影响本机，曲目按需加载，读取失败会单独提示。单人与本地合作继续使用原生音乐。分发包已包含 17 份去重音频和循环清单，不需要现场转换。

“画面”按钮切换 **自动／流畅／省性能**，在当前浏览器保存。“流畅”输出上限 60 Hz，“省性能”上限 30 Hz；自动模式在浏览器报告不超过 4 个逻辑核或不超过 4 GiB 内存时选择省性能。只减少画面转换与上传，不改变输入、游戏速度、碰撞或联机同步；设备若无法及时完成模拟计算，降低画面输出也不能保证满速。

原生多玉绘制、背景恢复、人物及 Boss 补画和等待循环保持原有优化。DOSBox-X 直接提交完整 RGB WebGL 画面；联机每批锁步推进后提交最新画面，音效在确认后播放。本地使用 Simple CPU 和自动 cycles，联机使用固定 30000 cycles，游戏仍由原作时钟定速。联机核心复用 TH03 的通用调度、受保护的同步解释器与分块内存比较，未启用 TH03／TH04 的专用游戏地址忙等优化，也未加入回滚。

2026-10-15 桌面短测：三人八玉本地合作约 **56.5 个实际游戏帧／秒**；两个独立联机内核的三人八玉、人物输入和原作暂停／恢复通过 9 次状态校验；真实本机三人 WebSocket、WebRTC 房间均共同确认到第 480 步，第三人离开后其他端停止。这些结果不代表手机、跨网联机或完整通关性能。

当前联机协议为 `th01-dosbox-lockstep/3`，不能与旧 NP21 版联机。更新后重启服务，全员关闭旧页、刷新并重新建房。历史 NP21 资源暂留供维护对照，普通入口只使用 DOSBox-X。
