## 当前入口与核心约束（2026-10-21）

录像与观战不能给 DOS 游戏／模拟器执行路径新增指令、标记、端口回调或专用核心。浏览器侧压缩、输入历史、状态读取与传输可以消耗宿主 CPU；这与 DOS 虚拟 CPU 的执行预算分开判断。此前 4.78／4.31 ms 是宿主侧单步耗时，不是 DOS 指令性能测量。

- 单人：`solo.html` 默认开启浏览器 Replay，使用普通单人磁盘与普通 WASM，不覆盖 `MAIN.EXE`／`MAINE.EXE`。记录本次启动的宿主时钟、按键及触控；退出本局或点“提前结束录制”后，可保存 `.th05r`，游戏继续。再次录制须“重新开始”。录制时使用原版模拟音源；关闭录制可选择独立 BGM。`solo-original.html` 保留不录制入口。
- 单人播放：`solo-replay.html` 导入新的浏览器录像，自动重演启动、菜单、剧情和暂停；播放页可暂停／继续。`solo-legacy-replay.html` 仅播放旧游戏帧格式，允许使用专用回放核心，不再提供旧方案录制；两种文件都严格校验资源身份。
- 多人：`lan.html` 保留浏览器侧完整确认历史录制、途中导出和本机／HTTP 观战；浏览器另开独立旁观 Worker 生成可移植检查点，正在操作的 DOS 实例不做快照、不等待该 Worker。`coop-replay.html` 的定位与 Live 优先恢复最近检查点，再逐帧验证剩余输入。
- 旧插桩分面实验：房间不能开启，Worker 在读取专用资源前拒绝实验启动。旧分面文件也不能在正式入口播放；实验资源与诊断保留用于后续研究。新的按面定位使用下面的浏览器检查点。
- 长历史：换面后的已确认批次边界、每 1800 同步帧（约 30 秒）及结束尾部生成检查点，文件、本机和 HTTP 旁观均可携带。新观众也可直接恢复，不依赖以前看过的本机缓存。“按面定位”列出已经生成检查点的第 2–6 面；这不是精确卡在原生换面第一条指令的独立面录像。

检查点包含整机和浏览器宿主状态，继承随机数、资源、分数、动态对象与文件状态。第一次恢复需加载共用基准，后续点按该基准差分压缩。新录像容器为 `T05MP003`；没有检查点时仍导出纯确认历史。后台尚未追上、旧文件没有点、检查点损坏或容量已满后的区间，仍可从确认历史重建，可能等待更久。输入历史仍完整下载，优化的是游戏执行前缀，并非视频或只下载当前关。

每局最多 128 个点、压缩合计 128 MiB、单点 16 MiB；HTTP 服务检查点总额另限 256 MiB。到达上限只停止新增检查点，玩家游戏、完整输入录制与既有检查点继续。正常跟播保持原速，剧情及原生菜单自动重演。此功能目前用于多人 `.th05m` 和旁观，单人 `.th05r` 沿用当前播放器。

浏览器录制格式为 `T05EXT02`／`th05-external-jspi/2`，独立压缩时钟与输入；与旧 `T05FRM03` 游戏帧格式不互换。不限速辅助作废当前未保存录像；压缩失败、超限或超时只停止录制，不停止游戏。生成文件后点击“保存 Replay”或“丢弃录像”；刷新／重新开始前请先保存。

本轮没有重建或修改普通游戏磁盘／WASM，也没有部署或重启服务。资源身份改变时旧文件需匹配原版本，不绕过身份校验。中日文短样本、独立实例回放与录制故障隔离已验证；完整通关、长时跨关、实体移动端尚未验收。原单人页面已留本地备份于 `reports/before-browser-only-policy-20261021/`。验证与历史结果见 [验收状态](REPLAY-STABILITY.md)。

## 此前 Replay 实现记录（历史；入口状态以上节为准）

10 月 21 日扩展实测发现：来源先运行 6000 个同步步，再用测试触发的原生加载进入第 2 面，新观众在重建后的第 359 次原生更新前发生状态校验失败，RNG 和火花游标出现差异。分面入口虽已接通，较长前史下的正确性尚未达标；请保持“分面观战”默认关闭。短样本通过不代表此问题已解决，详情见 [验收状态](REPLAY-STABILITY.md)。

已加入玩家优先的故障隔离：压缩失败／积压只停止本局录制，游戏继续；观众接收或网络上传积压只停止对应旁观通道。途中导出分批压缩，本机观众分批接收，不在玩家页面一次性复制整局。仍有输入采样、校验和压缩成本，尚未证明所有设备零性能影响。该轮调整改变单人资源身份，旧 `.th05r` 需重新录制。

本节及后续分面使用描述保留历史状态，当前功能以文首“当前入口与核心约束”为准。技术规格见 [实现说明](REPLAY-IMPLEMENTATION.md)，已测和待测范围见 [验收状态](REPLAY-STABILITY.md)。

分面独立播放已接入多人文件、本机旁观和 HTTP 旁观。房主在开局前把“分面观战”设为开启（默认关闭），全员加载相同的独立分面资源；观看页可用“按面播放”选择有记录的第 2–6 面，晚加入或定位可跳过更早的关卡。浏览器记录固定 490 字节的初始化状态与本面原生输入，剧情和原生菜单自动跟随来源操作。随机数、累计计数和各席内部统计也会继承，不能只同步资源与 1P 显示分数。第 1 面、EX、分面数据缺失或不可验证时使用完整确认历史；队友离线会停止本局后续分面采集。已有旧录像不会自动获得分面数据。

保存菜单用方向键选择、Z／Enter 确认，也支持鼠标与触屏；弹出时须先释放已按住的操作键。关闭或刷新整个网页不能保证弹出保存菜单，请先结束本局并保存。回放片段结束不等于游戏通关。

单人启用无敌或不限速移动后，本局未保存录像立即作废；关闭设置后要到原生下一局才恢复录制。多人任一席使用不限速移动，所有玩家本局未保存录像作废，观战继续并显示作弊提示。已下载的干净前缀无法撤回。`/solo-original.html` 保留原版触控／模拟音源，使用该入口不录制。

当前单人格式为 `th05-game-input/3`（`T05FRM03`，6 字节／战斗输入帧）；多人使用 `.th05m`，纯同步历史为 `T05MP001`，附带分面索引为 `T05MP002`。多人历史 schema 仍为 `th05-confirmed-input/1`，文件头、联机与旁观均要求 `th05-netplay/9`。新版读取两种多人容器，但仍检查资源身份；资源身份不一致或更旧格式／协议的录像需重新录制，勿绕过检查。单人与多人文件不能互换。部署时完整替换资源及 Python 模块（包含 `lan_stage_history.py`），重启服务，全员刷新并重新建房。

跨设备观看链接须使用观众可访问的局域网／公网地址，不能直接分享 `127.0.0.1`。本机旁观链接仅限同浏览器同源。网络历史只在服务器内存临时保留：每段最多 216000 同步步，最多 16 段，发布者停止活动 15 分钟后清理，服务器重启即丢失；观看读取不延长期限，长期保存请导出文件。旁观目前未接入 `eagler-touhou` 主项目大厅。

分面方案已验证独立核心跳过前缀、原生剧情自动播放、回滚后确认发布、HTTP 独立观看和采集失败隔离；完整自然主线／EX、连续自然跨面、实体跨设备公网、移动端长局和长期内存仍待验收。10 月 20 日原有一万余帧从头追赶测试仍为失败，不将新方案样本记作原测试通过。普通磁盘与核心保留；开启分面设置才加载新增标记的专用磁盘／WASM，记录与传输仍由浏览器负责，DOS 不保存录像。采样与压缩仍有成本，未证明所有设备零性能影响。此轮更新改变多人资源身份，旧身份文件需重新录制；尚未部署或重启现有服务。具体结果见 [稳定性说明](REPLAY-STABILITY.md)。

## 启动

需要 Python 3.10 或更新版本，以及新版 Chrome / Edge。单人、本地合作需要浏览器支持 WebAssembly JSPI。通过 HTTP 服务打开页面，不能直接双击 HTML 文件。

| 模式 | 启动方式 | 地址／端口 |
| --- | --- | --- |
| 原版单人 | `start.bat`，首页选择“单机游戏” | `http://127.0.0.1:9866/solo.html` |
| 本地双／三人 | `start.bat`，首页选择“本地多人” | `http://127.0.0.1:9866/local.html` |
| 双／三人局域网 | `start-lan.bat` | 默认 9893，队友使用终端显示的局域网地址 |
| 公网联机 | `start-public.bat` 或部署 `lan_server.py` | 默认 9893，使用可从互联网访问的服务地址 |

命令行也可启动：

```sh
python server.py
python lan_server.py
```

本地服务仅监听本机；手机或平板访问时使用局域网服务。端口被占用时可手动指定，例如 `python server.py --port 9891 --no-browser` 或 `python lan_server.py --port 9894`，以终端显示的地址为准。

WebSocket 中继需要额外安装依赖：

```sh
python -m pip install -r requirements-lan.txt
```

### 局域网加入

1. 房主运行 `start-lan.bat`，所有设备连接同一局域网。
2. 所有人打开房主终端显示的地址，如 `http://192.168.1.20:9893/lan.html?network=lan`。队友不要输入 `127.0.0.1`。
3. 房主创建房间，选择人数、难度、语言、初始残机／Bomb 及回滚开关；队友输入四位房间号加入。
4. 各自选择座位和角色，全员准备后由房主开始。共同设置发生变化时需要重新准备。

### 公网加入

所有人访问同一个已部署的公网网址和房间服务。公网默认 STUN 辅助 WebRTC 直连，连接失败时整房回退到已部署的 WebSocket 中继；也可在大厅“连接方式”中选择始终中继。

`start-public.bat` 使用 `--network public-rtc`，不会自动配置公网 IP、端口映射或隧道。旧 `network=public-ws` 链接保留强制中继行为。HTTPS、反向代理和 STUN／TURN 配置见 [公网部署说明](README-PUBLIC.md)。

## 操作

| 玩家 | 移动 | 射击 | Bomb | 低速 |
| --- | --- | --- | --- | --- |
| 单人／本地 P1 | 方向键 | Z | X | Shift |
| 本地 P2 | W / S / A / D | J | L | K |
| 本地 P3 | T / G / F / H | V | B | N |

联机每台设备只控制自己的座位，使用方向键或 WASD 移动、Z / J 射击、X / L 释放 Bomb、Shift / K 低速。

Esc 或屏幕暂停按钮打开游戏自带的暂停菜单；方向键选择，Z / Enter 确认，Esc 继续。选择退出会关闭模拟器并结束本局。联机任意席可操作共同暂停菜单，退出在输入确认后生效。

触屏支持单指拖动、第二指低速、自动开火开关、Bomb／双击 Bomb、限速／不限速、灵敏度、判定点和横竖屏独立布局。通过屏幕控件调整触屏布局，支持全屏及截图。本地多人可选择触屏操作的席位。

原版单人保留开头、标题菜单、选人和原作规则，仅加入触摸输入及状态接口。合作模式在网页设置人数、角色和难度后直接进入关卡，Extra 直接进入 Extra 关。

## 合作规则

幽香的异色残影已接入：同角色第二次出现为暖色衣服＋蓝紫残影，第三次为紫红衣服＋青蓝残影，第一次保留原版。残影使用预览素材的独立 RGB 显示，三种姿态均生效；服装继续使用原生色阶，射弹使用下述逐弹种 RGB 方案，幽灵保持原方案。本机及联机（含回滚）共用此效果。

- 不同角色使用原色；同一角色按 P1 → P2 → P3 的出现顺序，依次使用原色、备用色一、备用色二。灵梦／魔理沙备用色为蓝、绿，魅魔／幽香为暖色、紫红；幽灵沿用该玩家的配色，救援复活后保持一致。实战主弹、副弹及其命中特效按源帧独立选色，右侧机型标记使用对应主弹颜色；子机及未使用附属图块保持原色。射弹使用审核素材的独立 RGB，服装仍使用 PC-98 原有色阶，保留坐骑原色。
- 每席独立生命、Bomb 和 Power；分数、高分、点、梦、擦弹及其结算计数为全队共用。Boss 血量仍按人数调整，双人 ×1.5、三人 ×2.2；得分固定采用原版 ×1。合作侧栏以原生整数显示 Power，例如 `P 72/128`，上限保持 128 P。拾取补正为双人 ×1.5、三人 ×2：小 P 分别交替增加 1／2 点、固定增加 2 点，大 P 分别增加 15／20 点，各席位独立保留半点余量。P 值固定占三格，右侧残机与 Bomb 上下对齐。
- Power 优先归拾取者，已满火力时大小 Power 支援最低火力的存活队友；Bomb 道具奖励所有存活席位；1UP 给全队加命，并复活已彻底死亡的队友。已确认离线的席位不参与道具奖励和救援。团队分数达到 Extend 阈值时，全队同样按 1UP 规则加命／复活。
- 彻底死亡后显示幽灵，位于存活自机和僚机下方。靠近队友，按住低速并停火 90 游戏帧可转移一条生命；救活幽灵时，救援者 Bomb 减半，被救者得到一个 Bomb。
- Bomb 库存独立，原版世界同一时刻运行一个 Bomb 演出。已修正交替释放时绘制回调改写寄存器导致的资源串用。
- 背景、敌人、弹幕、道具及公共弹池仍按原版世界更新；个人 HUD 显示对应席位资源。

可使用原版模拟音源或浏览器独立 BGM。资源／编译缓存用于加快后续启动，每次开局创建新的模拟器实例；游戏进度、高分和本局内存不持久保存。

启动时并行读取磁盘、编译核心和准备素材；已校验的残影素材也使用资源缓存。游戏初始化期间复用状态签名候选位置，减少对整个模拟器内存的重复扫描。更新后重启服务并刷新页面，使所有客户端使用同一前端构建。

## 联机与性能

当前协议为 `th05-netplay/9`。开局校验房间配置、游戏盘、引擎及前端构建身份，各端必须使用同一版本；更新后重启服务，全员关闭旧页、刷新并重新建房。

断线处理对齐 TH04：连接异常后保留本局并等待 5 秒恢复；无数据超过 3 秒也会进入恢复等待。直连会重新协商数据通道，中继会重建当前玩家的连接，恢复后补齐输入和同步校验。房间状态请求暂时失败时继续保留游戏连接并重试。客机超时后，由房主与其余在线玩家确认共同离线帧，离线角色转为本局永久幽灵，其余玩家继续；房主恢复超时则结束本局。暂停和回滚同样遵守此规则。恢复限于原页面仍保留本局的情况，刷新页面或关闭后重新加入不能接回进行中的游戏。

回滚默认关闭，开启后允许先预测输入，收到真实输入后纠正。直连和中继均使用 6 步方向预测、最多 6 步预测领先，并保留 12 步恢复历史；本地额外输入延迟为 0。6 步是预测领先上限，不是固定增加的输入延迟。主页面推进与 Worker 补算共用此限制，减少多人持续移动、变向时的无效重算。

联机核心已接入原生帧内调度、受保护同步解释器、TH05 专用 VSync 等价忙等合并、分块内存比较和 PC-98 显存查表。回滚开启且浏览器支持多内存时使用写入记录核心；不支持时使用完整复制回退。画面仅保留最新完整帧，触摸可操作状态随每步模拟更新。

页面显示游戏帧率、每步计算耗时、RTT、输入等待占比和回滚信息，便于区分模拟计算不足与网络等待。开启回滚需要额外计算和内存；慢端仍会限制共同推进速度，中继的网络波动也可能造成停顿。

2026-10-15 的 TH05 忙等、预测限速、原生暂停、Bomb 与幽灵图层等最新修改已完成对应构建或语法解析，尚未完成新一轮游戏、弱设备和异地公网验收。历史公共优化核心在 SM-T500 的无网络短测约 18.64 游戏帧／秒，该数字不代表当前完整版本，也不代表实际联机性能。不能保证低端设备或所有弹幕场景满速。
